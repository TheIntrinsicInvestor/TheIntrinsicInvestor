## Hi, I'm Brian

I study Accounting and Finance at LSE in London. I started writing code because I wanted to test trading ideas properly instead of just arguing about them. It turned into the part of finance I enjoy most.

### What I spend my time on

**Options and volatility research.** I pull institutional data, backtest an idea, and publish the result whether or not it works. A few I like:

- Following Congress trades looks smart until you check the disclosure lag. The median is 27 days, so the move is usually over before you can see the trade.
- Selling straddles into earnings won 69% of the time across 37,508 S&P 500 events.
- The wheel strategy on SPY lowered drawdowns a bit and still lost to buy and hold.

All of it is at **[theintrinsicinvestor.com](https://theintrinsicinvestor.com)**, and the source is in [Backtesting](https://github.com/TheIntrinsicInvestor/Backtesting).

**Building tools for my own problems.** A Telegram bot that pings me when a new internship listing appears. A route generator that makes proper running loops. A live F1 timing screen. A guitar amp rig running on my PC. If I keep wishing something existed, I eventually build it.

**Hackathons.** I like the pressure of a short deadline and a real problem, and I'm looking for more of them in London.

### How I work

I build a lot with Claude Code. I care more about whether the thing is correct than who typed each line, so I read what it writes, run it, and check the numbers before I trust them. If a backtest looks too good, I assume I made a mistake first.
